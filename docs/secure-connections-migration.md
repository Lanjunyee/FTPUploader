# 安全协议配置迁移与回退

旧站点缺少 `transport` 字段时按普通 FTP 加载，缺少编码时按自动加载；UUID、目录、端口和用户名保持不变。配置首次保存前，原始旧格式数据备份到应用偏好 `ftp.savedSites.beforeSecureProtocols`，备份不会被后续保存覆盖。普通配置不包含密码。

钥匙串服务由 `local.schoolftpuploader.ftp-sites` 迁移到 `.v2`。新记录包含协议与 TLS 模式（四种 transport 值）。只有普通 FTP 且服务器、端口、账户和登录方式完全匹配时才能读取旧记录。先成功写入新记录，再清理旧记录；任一步失败均报告错误，失败时旧源记录仍保留。成功迁移后继续从新记录读取。协议变化不能继承原密码，须重新输入。

回退前退出应用并备份当前偏好与钥匙串记录；使用 macOS 偏好工具将 `ftp.savedSites.beforeSecureProtocols` 中的原始 Data 恢复到 `ftp.savedSites`，然后运行旧版。不得用旧版直接加载并保存新协议配置，以免丢失安全模式。已成功迁移并删除旧记录的密码无法由旧版读取，应在旧版重新输入并明确保存；不导出明文密码或自动逆向复制钥匙串。没有旧备份时保留新版数据，重新创建旧版 FTP 站点，不把 FTPS/SFTP 当普通 FTP。


## 私钥认证字段兼容

缺少 `authenticationMethod` 的旧站点和 v2 钥匙串身份按 `password` 读取，旧密码记录继续使用原 v2 服务。私钥身份不会读取或写入密码钥匙串。站点新字段 `privateKeyReference` 只含只读安全书签、显示名称和 SHA-256 内容摘要，不含私钥字节或口令。旧匿名和显式空密码行为不变。

密码站点切换到私钥时，保存流程先清理该站点的旧密码，再保存新配置；清理失败会报告错误并保留原配置及编辑草稿，不虚报成功，不读取其他站点密码。配置写入失败同样不会提交新配置，但已经删除的旧密码可能需要重新输入，不能恢复明文秘密。取消编辑不保存关联；删除站点只清理配置及该站点凭据，不删除源私钥。

降级前备份当前配置。旧版本不能识别私钥认证字段，不能用旧版本直接编辑私钥站点；在旧版本重新建立支持的密码站点并明确输入密码，不将私钥关联当作密码或自动降级为 FTP。
